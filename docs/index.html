    @fireblocks/custom-sdk

    Fireblocks SDK Framework

    A TypeScript framework for building custom Fireblocks blockchain SDKs. Fork or copy this repository and implement the blockchain-specific stubs to create a production-ready SDK for your target chain.

    What This Is

    This is a developer framework, not a ready-to-use SDK. It provides:

    • A complete project scaffold with two SDK class templates
    • Lazy per-vault state caching (public key + address resolved on first use)
    • An optional Express REST API layer with Zod validation
    • Fireblocks API integration via FireblocksService
    • A BlockchainApiService with stub methods you implement for your specific blockchain
    • Built-in resilience patterns, logging, and error handling

    Your job as an SDK builder is to implement the stubs in BlockchainApiService and wire up the SDK classes for your blockchain.

    Which SDK Class to Use

    The framework ships two SDK variants. Choose based on how well Fireblocks supports your target blockchain:

    MainSDK SemiSupportedSDK
    Use when Fireblocks has no native support for your chain Fireblocks can sign but not broadcast (partial support)
    Signing External — via fireblocksSigner.ts Via Fireblocks raw signing
    Broadcasting Via BlockchainApiService.broadcastTransaction() stub Via BlockchainApiService.broadcastTransaction() stub
    Address derivation Required — implement formatAddress() stub Required — implement formatAddress() stub
    Vault init Lazy — public key and address resolved on first use per vault, cached in a map Per-call — vaultAccountId passed to each method

    Getting Started

    # 1. Fork or copy this repo for your new SDK project

    Key Extension Point: BlockchainApiService

    src/services/blockchain.api.service.ts is the core file you must implement. It contains stubs for every blockchain-specific operation:

    export class BlockchainApiService {
      constructor(testnet: boolean = false);

      // Derive a blockchain address from a BIP32 public key
      formatAddress(pubKey: string): string;

      // Fetch native coin balance for an address
      getNativeBalance(address: string): Promise<number>;

      // Fetch fungible token balances for an address
      getFTBalancesForAddress(address: string): Promise<{ token: TokenType; balance: number }[]>;

      // Estimate transaction fee
      estimateTxFee(): Promise<number>;

      // Build an unsigned transaction object
      buildUnsignedTransaction(sender, recipient, amount, type?, token?): Promise<UnsignedTransaction>;

      // Serialize the unsigned transaction to bytes for signing
      serializeTransaction(sender, recipient, amount, type?, token?): Promise<UnsignedTransaction>;

      // Broadcast a signed transaction to the network
      broadcastTransaction(signedTransaction: unknown): Promise<BroadcastResult>;

      // Fetch transaction history (parsing logic example is provided)
      getTransactionHistory(params: GetTransactionHistoryParams): Promise<Transaction[]>;
    }

    getTransactionHistory includes working example parsing logic for native and fungible token transfers. Adapt the fetch call to your specific blockchain API or indexer.

    SDK Classes

    MainSDK (src/MainSDK.ts)

    For blockchains with no native Fireblocks support. A single instance serves all vault accounts — per-vault public key and address are resolved lazily on first use and cached internally.

    import { MainSDK } from "./MainSDK";
    import { BasePath } from "@fireblocks/ts-sdk";

    const sdk = new MainSDK({
      apiKey: process.env.FIREBLOCKS_API_KEY!,
      apiSecret: process.env.FIREBLOCKS_SECRET_KEY!,
      basePath: BasePath.US,
    });

    // Vault address operations (via Fireblocks API)
    const address = await sdk.getVaultAccountAddress("vault-123", "BTC", 0);
    const addresses = await sdk.getVaultAccountAddresses("vault-456", "ETH");

    // Native and token balances (vault data resolved lazily on first call)
    const nativeBalance = await sdk.getBalance("vault-123");
    const ftBalances = await sdk.getFtBalances("vault-123");

    // Send native coin
    const txResult = await sdk.createNativeTransaction(
      "vault-123",
      "recipient-address",
      1.5,
      false, // gross transaction
      "optional note"
    );

    // Submit a raw Fireblocks transaction (waitForCompletion must be true)
    const result = await sdk.submitTransaction("vault-123", {
      operation: TransactionOperation.RAW,
      source: { type: "VAULT_ACCOUNT", id: "vault-123" },
      assetId: "MY_ASSET",
      extraParameters: { rawMessageData: { messages: [{ content: "..." }] } },
    });

    // Transaction history
    const history = await sdk.getTransactionHistory("vault-123", { limit: 20, order: "DESC" });

    // Access underlying services directly
    const fireblocksService = sdk.getFireblocksService();
    const blockchainService = sdk.getBlockchainApiService();

    await sdk.shutdown();

    SemiSupportedSDK (src/SemiSupportedSDK.ts)

    A lighter template for blockchains where Fireblocks can sign but not broadcast. No per-vault caching — vaultAccountId is passed explicitly to every method. Extend this class to add the operations your blockchain requires.

    import { MainSDK as SemiSupportedSDK } from "./SemiSupportedSDK";
    import { BasePath } from "@fireblocks/ts-sdk";

    const sdk = new SemiSupportedSDK({
      apiKey: process.env.FIREBLOCKS_API_KEY!,
      secretKey: process.env.FIREBLOCKS_SECRET_KEY!,
      basePath: BasePath.US,
    });

    // Vault address operations
    const address = await sdk.getVaultAccountAddress("vault-123", "BTC", 0);
    const addresses = await sdk.getVaultAccountAddresses("vault-123", "ETH");

    // Public key retrieval (BIP-44 path)
    const pubKey = await sdk.getPublicKey("vault-123", "ADA", 0, 0);

    // Submit a raw Fireblocks transaction
    const result = await sdk.submitTransaction("vault-123", transactionRequest);

    // Access underlying services directly
    const fireblocksService = sdk.getFireblocksService();
    const blockchainService = sdk.getBlockchainApiService();

    await sdk.shutdown();

    REST API Server

    The framework ships a ready-to-use Express server that wraps MainSDK operations. Start it as a standalone service or extend it with additional routes.

    Start the Server

    # Set up environment variables
    cp .env.example .env
    # Edit .env with your credentials and RPC_URL

    npm run build && npm start

    Endpoints

    All routes are mounted under /api.

    Get a Vault Address

    GET /api/vaults/:vaultAccountId/addresses/:assetId?index=0

    curl "http://localhost:8000/api/vaults/123/addresses/BTC?index=0"

    Get All Vault Addresses

    GET /api/vaults/:vaultAccountId/addresses/:assetId/all

    curl "http://localhost:8000/api/vaults/123/addresses/ETH/all"

    Submit a Transaction

    POST /api/vaults/:vaultAccountId/transactions

    curl -X POST http://localhost:8000/api/vaults/123/transactions \
      -H "Content-Type: application/json" \
      -d '{
        "transactionRequest": {
          "operation": "RAW",
          "source": { "type": "VAULT_ACCOUNT", "id": "123" },
          "assetId": "MY_ASSET",
          "extraParameters": { "rawMessageData": { "messages": [{ "content": "..." }] } }
        },
        "waitForCompletion": true
      }'

    Get Transaction History

    GET /api/vaults/:vaultAccountId/transactions?assetId=BTC&limit=10&offset=0&status=COMPLETED&startDate=2024-01-01&endDate=2024-12-31

    curl "http://localhost:8000/api/vaults/123/transactions?limit=10"

    Per-Vault State Caching

    MainSDK holds a single shared FireblocksService and BlockchainApiService. Per-vault identity data (public key and derived address) is resolved lazily via ensureVaultData() on the first call for each vault and cached in an internal map for all subsequent calls.

    import { MainSDK } from "./MainSDK";
    import { BasePath } from "@fireblocks/ts-sdk";

    // One instance serves all vault accounts
    const sdk = new MainSDK({
      apiKey: "...",
      apiSecret: "...",
      basePath: BasePath.US,
    });

    // First call for "vault-123": resolves pubkey + address via Fireblocks, caches the result
    const balance = await sdk.getBalance("vault-123");

    // Subsequent calls for the same vault use the cached VaultData — no extra Fireblocks round-trip
    const history = await sdk.getTransactionHistory("vault-123", { limit: 10 });

    // Graceful shutdown clears the vault cache
    await sdk.shutdown();

    Configuration

    Environment Variables

    Copy .env.example to .env:

    # Fireblocks credentials
    FIREBLOCKS_API_USER_KEY=your_api_key
    FIREBLOCKS_API_USER_SECRET_KEY_PATH=./secrets/fireblocks_secret.key
    BASE_PATH=US                   # US | EU | SANDBOX

    # Blockchain RPC
    RPC_URL=https://mainnet.example.com

    # Server
    PORT=8000
    APP_NAME=fireblocks-sdk-framework
    LOG_LEVEL=INFO

    Programmatic Config (Library Mode)

    When embedding the SDK as a library (no .env file):

    import { initConfig } from "./utils/config";

    initConfig({
      PORT: 8000,
      FIREBLOCKS: {
        apiKey: "your-api-key",
        secretKey: "your-secret-key",
        basePath: BasePath.US,
      },
    });

    getConfig() lazily loads from environment on first call; resetConfig() clears the cache (useful in tests).

    Extending the Framework

    Adding a New Operation

    1. Implement the logic in BlockchainApiService (or FireblocksService for Fireblocks-native ops).

    2. Expose it on MainSDK (src/MainSDK.ts):

    public async myCustomOperation(
      vaultAccountId: string,
      params: MyParams
    ): Promise<MyResult> {
      return await this.blockchainApiService.myCustomOperation(params);
    }
    1. Add a controller method (src/api/controllers/controller.ts):
    public myCustomOperation = async (req: Request, res: Response) => {
      const { vaultAccountId } = req.params;
      try {
        const result = await this.sdk.myCustomOperation(vaultAccountId, req.body);
        res.status(200).json({ success: true, data: result });
      } catch (error: unknown) {
        this.handleError(error, res, 'myCustomOperation');
      }
    };
    1. Add a Zod schema (src/api/validation/schemas.ts) and register the route (src/api/router.ts):
    router.post(
      "/vaults/:vaultAccountId/custom-operation",
      validate({ params: vaultParams, body: myCustomSchema }),
      controller.myCustomOperation
    );

    Adding Custom Types

    // src/types/custom.ts — add to existing file
    export enum TokenType {

      MyToken = "MY_TOKEN", // ← add your tokens here
    }

    Error Handling

    Use SdkApiError for structured errors:

    import { SdkApiError } from "./types/errors";

    throw new SdkApiError(
      "Invalid address format",
      400,
      "VALIDATION_ERROR",
      { address: providedAddress },
      "BlockchainApiService"
    );

    ApiController returns structured JSON for SdkApiError instances and a generic 500 for all others.
